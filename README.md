# 또링 가계부 소개 사이트

**또링 가계부** — 나 · 가족 · 여행, 가계부 세 권을 한 앱에서 — 를 소개하는 사이트다. 주소는 `https://ddoring.dabutdev.com`
(전에는 앱 이름이 달살림이라 `dalsalim.dabutdev.com` 이었다 — 옛 주소는 새 주소로 넘긴다, 아래 「배포」).

앱 저장소와 따로 둔다. 이 저장소는 앱의 코드도 데이터도 읽지 않는다.

## 명령어

```bash
npm install
npm run dev            # http://localhost:3000
npm run build          # 타입 검사 + 정적 파일을 out/ 에 만든다
npm run lint
npm run format         # prettier --write .

npm run check          # 빌드 결과(out/)를 띄워 동작을 확인한다 — 먼저 build
npm run render:og      # 공유 미리보기 그림을 다시 찍는다
npm run shots -- <폴더>  # 앱 화면 캡처(1080x2400)를 홈이 쓰는 WebP 로 public/shots/ 에 넣는다
```

`check` 와 그림을 찍는 명령은 브라우저가 필요하다. 처음 한 번 `npx playwright install chromium` 을 돌린다.

## 어떻게 만들어지나

Next.js 의 **정적 내보내기**다 (`next.config.ts` 의 `output: "export"`). 빌드할 때 모든 페이지가 HTML 로 만들어져
`out/` 에 놓이고, 서버 없이 그 폴더만 올리면 된다. 검색 엔진은 완성된 HTML 을 읽는다.

```
src/
  app/              페이지 — 폴더가 곧 주소다. 페이지는 조각을 배치만 한다
  components/       여러 페이지가 같이 쓰는 조각 (머리 · 꼬리말 · 로고 · 폰 틀 · 구조화 데이터)
    home/           홈의 구역 하나가 파일 하나 — 컴포넌트와 그 스타일이 나란히 있다
  config/           사이트 이름 · 문의처 · 바깥 링크(site) · 사이트 안의 주소와 메뉴(routes) · 테마(theme)
  lib/              도메인을 모르는 작은 함수 (금액 표기 · 그림 크기 읽기)
  styles/           디자인 토큰 (색 · 간격 · 모서리 · 폭)
scripts/            그림을 만드는 원본과 도구, 동작 확인
```

**읽는 방향은 한쪽이다** — `app → components → config · lib`. 아래 층이 위 층을 가져오지 않는다.

- **주소를 글자로 적지 않는다.** 링크 · 대표 주소 · 사이트맵은 `src/config/routes.ts` 의 `ROUTES` 에서 가져온다.
- **스타일은 뿌리 이름 아래에 둔다.** 홈은 `.home` — 그래서 다른 페이지로 새지 않는다.
  새 페이지를 만들면 뿌리 이름을 하나 정하고 그 아래에만 규칙을 쓴다. 여러 페이지가 같이 쓰는 것만 `globals.css` 에 올린다.
- **페이지의 머리 정보는 `pageMetadata()` 로 만든다** (`src/lib/metadata.ts`). 페이지에서 `openGraph` 를 따로 적으면
  위 층의 것이 통째로 갈려 공유 그림과 사이트 이름이 빠진 채 나간다.
- **화면 사진은 한 크기다.** 캡처를 모두 폭 540 의 WebP 로 줄여 싣고, 그 크기는 `src/components/Phone.tsx` 의 `SHOT` 한 곳에 있다.
- **도움말 · 약관 · 방침은 앱 서버의 페이지다.** 사이트에 페이지를 만들지 않고 `src/config/site.ts` 의 `HELP` · `LEGAL` 로 보낸다.

## 확인 (CI)

PR 과 `main` 에서 포맷 · 린트 · 빌드 · 동작 확인이 돈다 (`.github/workflows/ci.yml`).
동작 확인(`scripts/check.mjs`)은 lint 와 빌드가 못 보는 약속을 본다.

- 스크립트 없이 받은 HTML 에 본문이 있다 (검색 엔진이 읽는 것)
- 사이트맵의 모든 페이지에 제목 · 설명 · 대표 주소 · 공유 그림 · 사이트 이름 · 구조화 데이터가 있고, 제목이 서로 다르다
- 접근성 검사(axe · WCAG 2.2 AA)에 걸리는 것이 없다 — 모든 페이지를 밝게 · 어둡게로
- 바깥으로 나가는 요청이 없다. `public/_headers` 의 콘텐츠 보안 정책을 건 채로 콘솔 오류가 없다
- 테마 버튼이 바뀌고 기억된다 · 스크립트를 끄면 버튼이 숨는다
- 「움직임 줄이기」를 켜면 홈의 움직임(떠 있는 폰 · 흐르는 띠 · 빛 · 떠오르는 칸)이 멈추고 다 보인다
- 폭 360 에서 어느 페이지도 옆으로 넘치지 않는다. 브라우저의 글자를 두 배로 키워도 글자가 같이 커지고 넘치지 않는다
- 홈이 싣는 화면 사진 파일이 다 있고, 머리 메뉴가 가리키는 구역이 있다

페이지는 사이트맵에서 따라가므로 페이지를 더해도 이 파일을 고치지 않는다.

## 배포 (Cloudflare)

Cloudflare 대시보드의 **Workers & Pages → Create application → Import a repository** 로 이 저장소를 연결한다.
무엇을 올릴지는 `wrangler.jsonc` 가 정한다 — 서버 코드 없이 `out/` 만 올린다. 대시보드에 적는 것은 둘이다.

| 칸        | 값                    |
| --------- | --------------------- |
| 빌드 명령 | `npm run build`       |
| 배포 명령 | `npx wrangler deploy` |

Node 버전은 `.node-version` 이 정한다. `main` 에 머지하면 다시 빌드해 배포한다.
도메인은 만든 뒤 **Settings → Domains & Routes** 에서 `ddoring.dabutdev.com` 을 붙인다.

- 주소는 `ddoring.dabutdev.com` 이다. 바꾸면 `src/config/site.ts` 의 `url` 과 `scripts/check.mjs` 의 `SITE_URL` 도 같이 고친다 —
  대표 주소 · 사이트맵 · 공유 미리보기가 그 값으로 만들어진다.
- 옛 주소 `dalsalim.dabutdev.com` 은 지우지 않고 Cloudflare 의 리다이렉트 규칙으로 새 주소에 301 로 넘긴다 —
  이미 퍼진 링크와 검색 결과가 끊기지 않는다.
- 응답 헤더는 `public/_headers` 가 정한다 (Cloudflare 가 읽는 파일).
- 🔴 **Cloudflare 의 방문 통계(Web Analytics)를 켜지 않는다.** 켜면 방문자 정보를 받게 되어 아래 「지킬 것」이 깨진다.

## 고칠 때

| 무엇을                | 어디를                                                                                                                                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 받기 버튼을 연다      | `src/config/site.ts` 의 `PLATFORMS` 에서 그 플랫폼의 `storeUrl` 을 채운다. 눌리지 않던 상태 표시가 `storeLabel` 이 적힌 버튼이 된다                                                                     |
| 머리에 메뉴를 더한다  | `src/config/routes.ts` 의 `NAV` 에 더한다 (홈의 구역이면 `SECTIONS` 에도)                                                                                                                               |
| 문의 주소 · 약관 링크 | `src/config/site.ts` 의 `SITE` · `LEGAL`                                                                                                                                                                |
| 색 · 간격             | `src/styles/tokens.css`. 주소창 색처럼 CSS 밖에서 읽는 색은 `src/config/theme.ts` 의 `META_COLORS` 도 같이 고친다                                                                                       |
| 홈의 화면 사진        | 앱을 **예시 데이터로** 띄워 밝게 · 글자 크기 기본으로 찍는다. `scripts/shots.mjs` 의 `NAMES` 에 이름을 넣고 `npm run shots -- <캡처 폴더>`. 실제 금액 · 이름 · 카드사 앱 이름이 찍힌 사진은 넣지 않는다 |
| 공유 미리보기 그림    | `scripts/og-image.html` 을 고치고 `npm run render:og`                                                                                                                                                   |

## 지킬 것

- **색 · 간격 · 모서리는 `src/styles/tokens.css` 의 변수로만 쓴다.** 값은 또링 가계부 앱의 것을 옮겨 적었다.
  컴포넌트에 hex 를 직접 적으면 어둡게에서 깨진다.
- **방문자에게서 아무것도 받지 않는다.** 방문 분석 · 쿠키 · 입력 칸 · 바깥 스크립트 · 바깥 글꼴을 넣지 않는다.
  넣게 되면 개인정보 처리방침에 적을 것이 생긴다 — 넣기 전에 그것부터 정한다.
  브라우저에 저장하는 것은 밝게 · 어둡게로 고른 값 하나뿐이고 어디로도 보내지 않는다.
- **약관 · 방침 · 계정 삭제 안내의 본문을 여기에 복사하지 않는다.** 원본은 앱 서버에 한 벌뿐이고, 꼬리말이 그 페이지로 보낸다
  (`src/config/site.ts` 의 `LEGAL`).
- **화면 그림에는 지어낸 값만 쓴다.** 실제 금액 · 사람 이름 · 가게 이름 · 결제 알림을 싣지 않는다.
- **다른 회사의 로고를 쓰지 않는다.** 스토어 배지 대신 글자 버튼, 카드사 대신 머리글자 타일이다.

### 접근성

- **글자와 바탕의 대비는 4.5:1 이상.** 읽어야 하는 글자를 투명도로 흐리게 하지 않는다 — 「준비 중」 같은 상태도 글자다.
  가장 흐린 글자색(`--ink-faint`)과 가족 색(`--kind-family`)은 이 때문에 앱보다 한 단 짙다.
- **글자 크기는 rem 토큰으로.** px 로 적으면 브라우저의 글자 크기를 키워 둔 사람에게 커지지 않는다.
- **꾸미는 화면 그림은 `aria-hidden`** 이고, 같은 내용이 글이나 `aria-label` 에 있어야 한다. 화면 사진에는 `alt` 를 적는다.
- **움직이는 것은 「움직임 줄이기」에서 멈춘다.** 멈춘 모습이 완성된 화면이어야 한다.

### 문구

- 해요체로 쓴다 (`~해요` · `~예요`).
- **또링 가계부는 소비를 평가하지 않는다.** 「절약」 「아껴요」 「달성」 「점수」 「많이 쓴 사람」 같은 말로 앱을 소개하지 않는다.
- **앱이 분류를 골라 준다고 쓰지 않는다.** 결제 알림은 「넣을지는 직접 고르거나 자동으로 넣게 할 수 있다」까지만 말한다.
- 붉은 글자는 「지난달보다 늘어난 금액」 한 곳에만 쓴다. 지출 자체에는 쓰지 않는다.
